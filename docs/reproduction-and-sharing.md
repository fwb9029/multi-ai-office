# 复现与分享边界

更新日期：2026-11-16。

本次公开的是多 AI 协作的思路文档和合成示例，供其他 AI 理解目标、拆分工作并继续实现。包内没有运行代码、浏览器扩展安装包、桌面安装程序或可直接使用的账号配置。示例不是真实用户任务，也不是可以据此自动执行的费用授权。

已有原型在一台 Windows 电脑上验证过部分流程。换机、跨平台和面向其他用户的安装验证仍是后续工作，不能承诺下载此文档包就能直接使用。

## 接手时先保持的规则

- 用户在协调者聊天中提出需求；协调者负责整理材料、派工、收回结果、检查和交付。
- 免费优先。免费通道失效、额度不足或未登录时，暂停并报告，不自动改走付费 API 或其他收费模型。
- 每次任务使用独立编号和成果目录。超时不等于执行失败；先查看原任务与已有文件，不自动重发，不覆盖原回执。
- 收到正文或生成文件只表示“已收回”。内容检查通过后才标为“已验收”，不能把连接成功、点击发送或响应结束当成业务完成。
- 仅发送本次任务需要的事实、规则和材料。其他工具不会因为收到一个本机路径，就自动获得协调者的记忆、Skill 或文件权限。
- 不默认扩大监测范围。项目派工、用户手动操作、其他聊天和其他电脑的活动，应分别明确来源和授权。

## 环境与准备

参考原型依赖 Windows、本机 Node.js、Edge，以及用户自行安装和登录的桌面应用。桌面浮窗使用 Windows PowerShell 与 WPF；独立的付费 API 备选实现还涉及 Python。接手者应根据自己的实现核验具体版本，不能把这些依赖全部理解为本包已经附带。

本机程序、应用安装路径和端口需要在目标电脑重新配置。登录、验证码、实名认证、账号购买和充值由账号本人处理；不能复制原作者的浏览器资料、Cookie、应用登录数据库或加密凭据。

如采用网页扩展桥接，本机连接密钥应在每台电脑重新生成，只供本机组件使用，不写入聊天、示例、截图或仓库。HTTP、WebSocket 和桌面调试连接只监听 loopback，例如 `127.0.0.1`，不因需要远程查看状态就直接暴露控制端口。

## 按真实需求逐步复现

### 1. 先确定一个小任务及验收条件

选择用户确实需要的短文或小文件任务，约定输入材料、输出形式和怎样算完成。先画清任务状态：等待执行、执行中、已收回待验收、已验收、异常待核查。

接手 AI 需要另行实现或整理运行代码。本包中的流程与合成示例用于明确接口，不应被当成已安装的执行器。

### 2. 先打通豆包网页写稿、改稿和收回

采用用户本人已登录的 Edge 豆包网页，先核实网页与桥接服务都可用。围绕同一个真实需求完成一次起草，再把前稿和具体修改意见一起传入，收回修改稿并由协调者检查。

实际提交应与用户正在使用的会话隔离，避免覆盖草稿或重置手动对话。一次提交后等待明确完成信号；超时则保留“结果不确定”，先核对原网页，不再次发送同一任务。

“免费网页优先”不是永久免费或不限量的保证；以该用户账号当时可用的范围为准。不要把网页路线与独立付费 API 的账号、计费或保存设置混为一谈。

### 3. 再加入 WorkBuddy 的本地文件任务

使用独立任务文件夹，明确允许读取的输入和允许写入的输出位置。先从范围小、可检查的实际文件任务开始，让协调者核对输出文件及内容，不只依赖应用中的完成提示。

现行本机记录已验证 WorkBuddy 5.11.3 的三类教学任务：演示文稿与 HTML、趣味配对练习、基于本地文件和 CSV 的学情报告，并完成报告修正。该证据不包含在线办公服务的完整读写验证，也不能推导出任意文件任务和长任务都稳定。已有账号可能涉及平台积分或费用，不能承诺此路线免费。

遇到等待超时，先检查原任务是否仍在运行、是否已有文件；用户要求修正时创建明确的新修订任务，保留初稿和旧回执。

### 4. 最后接入真实状态与可选的桌面展示

状态展示先接任务队列，区分“正在生成”“已交稿”和“等待验收”。连接状态只能说明控制通道是否可用，不能推断账号额度，也不能代表用户在其他网页或原生客户端中的手动任务。

如要汇总 Codex 跨聊天活动，必须由本人明确授权，并通过正常界面审核 Hook 的命令和范围；不要因下载本包就自动修改用户级配置。状态采集只保留必要的事件名、会话或轮次编号、时间，不保存提示词、正文、推理、工具参数或聊天日志副本。桌面展示不需要对外公开这些内部编号。

启用前已有的活跃会话应来自可信的真实状态快照，不伪造开始事件。响应结束不等于内容已经验收；同一轮继续运行应恢复忙碌，旧结束事件不能清除其他未结束任务。缺事件或长期静默应显示未知，不能推断为空闲。原型四类 Hook 没有过程心跳，静默超过 15 分钟会保守转为待同步；后续若要改变这一边界，应单独设计和验证。

### 5. DeepSeek Harness 作为可选的独立验证

原型只完成过一次由用户明确批准、使用既有余额的短文本派发与收回测试。它不属于已接通的普通免费聊天网页路线，也不代表文件操作或长期稳定性已经通过。

接手者如确实需要验证 Harness，应重新取得本次消费授权，明确用途和调用次数。文档、示例授权编号、原作者曾经的批准以及“连接成功”，都不能替代新用户的费用授权。桌面操作方式没有已经验证的硬性总费用封顶能力，不能承诺一个无法强制执行的金额上限。

不需要 Harness 时可跳过这一步；不得把它设为免费路线失败后的自动后备。

### 6. 再安排另一台电脑的验证

在独立环境重新安装所需组件、生成密钥、登录账号并确认权限。逐项验证小任务、异常暂停、重启不重发、成果核对和状态显示，再决定是否制作运行代码发布包或安装程序。

跨机验证完成前，公开说明应继续标为“本机原型经验与复现方案”，不要声称一键安装、无人值守或跨平台可用。
